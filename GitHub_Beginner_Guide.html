OVERVIEW

GitHub란 무엇인가?

GitHub는 코드를 저장하고, 팀과 함께 협업하며, 프로젝트를 관리하는 플랫폼입니다. Git 버전 관리 시스템을 기반으로 하며, 전 세계 수백만 명의 개발자가 사용합니다. Vantive-Kr 팀은 techwiki 저장소를 통해 기술 문서와 도구를 관리합니다.

저장소 (Repository)

프로젝트의 모든 파일과 변경 이력이 저장되는 공간. "Repo"라고도 불림.

브랜치 (Branch)

기존 코드에 영향 없이 새로운 기능을 개발하거나 실험할 수 있는 독립된 작업 공간.

커밋 (Commit)

파일의 변경 사항을 저장하는 행위. 각 커밋에는 변경 내용과 날짜/작성자 정보가 기록됨.

브랜치 선택기

현재 보고 있는 브랜치를 선택합니다. 기본값은 main 브랜치입니다. 다른 브랜치로 전환하여 해당 브랜치의 파일을 탐색할 수 있습니다.

파일 목록

저장소에 있는 모든 파일과 폴더가 표시됩니다. 파일을 클릭하면 내용을 확인하고 편집할 수 있습니다.

커밋 이력

몇 번의 변경이 있었는지 확인합니다. "15 Commits"를 클릭하면 전체 변경 이력을 시간순으로 볼 수 있습니다.

Add file / Code 버튼

Add file로 새 파일 업로드, Code 버튼으로 저장소를 다운로드(Clone)하거나 ZIP으로 내려받을 수 있습니다.

초보자 팁: 파일을 직접 GitHub 웹에서 편집하려면 파일 클릭 후 오른쪽 상단 연필() 아이콘을 클릭하세요. 간단한 수정은 로컬 설치 없이도 웹에서 바로 가능합니다.

Open / Closed 필터

현재 처리 중(Open)인 이슈와 완료(Closed)된 이슈를 구분해서 볼 수 있습니다.

라벨 (Labels)

bug, enhancement, documentation 등의 라벨로 이슈를 분류합니다. 커스텀 라벨도 만들 수 있습니다.

담당자 (Assignees)

이슈를 처리할 팀원을 지정합니다. 담당자로 지정된 사람에게 알림이 전송됩니다.

마일스톤 (Milestones)

버전 출시, 분기 목표 등의 마일스톤에 이슈를 연결하여 진행률을 추적합니다.

1

New issue 클릭

오른쪽 상단 녹색 버튼을 클릭하여 새 이슈를 작성합니다.

2

제목과 내용 작성

이슈 제목은 명확하게, 본문에는 재현 방법·스크린샷·기대 동작을 포함하면 좋습니다.

3

라벨·담당자 지정 후 Submit

오른쪽 패널에서 라벨과 담당자를 설정한 뒤 Submit new issue를 클릭합니다.

성공 (초록 체크)

워크플로우가 오류 없이 완료된 상태. GitHub Pages가 정상 업데이트됩니다.

실패 (빨간 X)

워크플로우 실행 중 오류 발생. 클릭하면 상세 로그를 확인하여 원인을 파악합니다.

실행 중 (노란 점)

현재 워크플로우가 진행 중. 파일 Push 직후 약 30~60초간 이 상태가 표시됩니다.

pages-build-deployment

HTML 파일을 GitHub Pages로 자동 배포하는 워크플로우. 코드 Push 시 자동 실행됩니다.

Vantive-Kr 활용 방법: techwiki 저장소에 HTML 파일을 업로드하면 Actions가 자동으로 실행되어 GitHub Pages에 배포합니다. 파일 업로드 후 1분 내에 웹에서 확인 가능합니다.

Secret Scanning (활성화됨)

GitHub API 키, 비밀번호, 토큰 등이 실수로 코드에 포함되면 즉시 알림. techwiki에 활성화되어 있어 보안 위협으로부터 보호됩니다.

Security Advisories (활성화됨)

저장소의 보안 취약점을 공개 전 비공개로 처리하고 패치 후 공개하는 관리 도구입니다.

Dependabot

사용 중인 외부 라이브러리에 보안 취약점이 발견되면 자동으로 업데이트 PR을 생성합니다. HTML 파일만 있는 경우 불필요합니다.

Code Scanning

JavaScript, Python 등 코드에서 보안 취약점을 자동 탐지합니다. 순수 HTML 저장소에는 선택적으로 활성화합니다.
